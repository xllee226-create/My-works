## 2. 问题分级清单

### 2.1 P0 必须解决（影响验收与答辩）

#### P0-1 「AI在哪里」—— 课程硬性要求的最大风险点
- **现状**：Demo 中"匹配证据、缺口、定制建议"全部是人工预写的静态数据；页面没有任何 AI 参与的理解/判断/生成过程展示。
- **风险**：作业要求"AI必须成为生产要素，而不只是营销标签"。讲师若追问"这些分析是AI生成的吗？如何复测？"，当前交付物无法证明 AI 参与了核心链路，容易被定性为"换皮的筛选器"。
- **已执行动作**：Demo 详情页新增「AI 推理过程」四步可视化（JD要求抽取 → 简历证据召回 → 差距/风险分析 → 定制建议生成），并标注"演示链路数据，接入真实大模型为下一阶段"，先证明产品链路设计成立。
- **建议后续动作**：MVP 1.1 接入真实 LLM（对 JD 做要求抽取、对简历做证据召回、生成建议），并把 50 岗中至少 10 岗改为"AI 生成+人工校验"，形成可复现的对照。

#### P0-2 匹配分是黑盒 —— 与产品卖点自相矛盾
- **现状**：详情页只显示一个总分（如94），没有五维得分，用户依然不知道"为什么"。
- **风险**：产品口号是"先解释为什么适合"，但分数本身不可解释，等于在自己的产品里复现了求职黑箱。
- **已执行动作**：详情页新增「匹配分拆解」——五维分数条（方向一致性30 / 经历证据25 / 产品与AI实践20 / 数据15 / 行业10），加权总分与展示总分一致（已脚本校验 50/50 通过）。
- **建议后续动作**：在岗位清单与方案中补充"评分卡样例"，让评分可复算、可审计。

#### P0-3 README 与目录不一致
- **现状**：`README-交付清单.md` 声称交付含 `职达27-课程作业汇报.pptx` 和 `职达27-课程作业-李昔伦.zip`，但 deliverables 目录中未发现这两个文件。
- **风险**：按清单提交邮件时缺附件，或按目录打包时清单失真，都会被讲师视为交付不规范。
- **建议动作**：请确认 PPT 与 zip 是否已生成。若已生成请放入目录；若未生成，请修订 README 去掉这两项或标注"待补充"。

### 2.2 P1 重要（短期应改进）

#### P1-1 需求证据链 n=1，且访谈对象=设计者本人
- **现状**：正式访谈只有用户本人；3位同专业同学仅作"待验证样本"，未完成访谈（文档已诚实标注，这是加分项）。
- **风险**："真需求"的客观性容易被质疑——样本是自证。
- **建议动作**：方案"后续实验"已有 A/B/C 设计，建议补充一段"多用户访谈计划"（2周内完成5名目标用户访谈、记录每周投递量与决策时长），形成"单用户验证 → 小样本复制"的递进证据链。

#### P1-2 数据时效性与可追溯性
- **现状**：① 4个 OPPO 实习岗发布于 2026-03-06（距今5个月）；② 部分来源为列表页/“2027校招页面”，非岗位详情页；③ 本次抽查发现 OPPO 官网为反爬保护页面（详见第4节）。
- **风险**：演示时若被当场打开链接，个别岗位可能已下线或变更，削弱"真实可追溯"的说服力。
- **已执行动作**：Demo 新增「数据时效」提示条与详情页「来源类型/核验日期」字段；方案可引用。
- **建议后续动作**：提交演示前人工复核 OPPO 系 4 岗在招状态；给每个岗位的来源链接保留"岗位ID+核验日期"双字段，便于快速复核。

#### P1-3 北极星指标存在"自我实现"漏洞
- **现状**：北极星指标为"可形成明确投递决策的比例 ≥80%"（42/50）。但"不建议投"也算形成了决策，该指标可由产品自己定义口径而达标。
- **风险**：指标无法反映决策质量（用户是否采纳、采纳后是否获得回应）。
- **建议动作**：补充行为指标——"直接可投岗位的队列采纳率""投递后获得回复/笔试邀请的比例"，作为 MVP 1.1 与 Pilot 阶段的北极星补充。

## 5. 答辩风险预判（讲师视角）

| 可能的追问 | 建议回答方向 |
|---|---|
| "AI 在哪里？它到底做了什么？" | 产品把 AI 限定在语义层（JD抽取/证据召回/差距解释/建议生成），规则层（硬门槛）与人工层（确认）兜底；Demo 用预置链路展示设计，MVP 1.1 接入 LLM 并用黄金测试集复测。强调"AI 是生产要素"的边界设计本身就是产品能力 |
| "你的匹配分是谁打的？凭什么可信？" | 五维加权评分卡（权重公开），50 岗同标准人工标注，分数可复算；下一步引入第二标注者一致性检验（如 Cohen's Kappa）或 LLM 对照 |
| "怎么证明这是真需求而不是你编的？" | 单用户深度访谈（本人，n=1）已诚实标注；痛点高频（周投1500-2000份）、有付费意愿上限（50元/月）与课程验收标准自证；Pilot 计划 5 名同专业用户复制验证 |
| "投递是模拟的，用户价值在哪？" | 价值在决策层（把不可解释的默拒拆成硬门槛/证据/人工三层），执行层是合规边界内的演示；商业模式靠决策价值付费，不靠自动投递 |
| "50 个岗位是你自己挑的，没有样本偏差吗？" | 是，已声明"当前只验证单用户"；负例覆盖能力/性质/城市薪资三类拒绝，用于证明系统会拒绝而非无差别推荐；多用户样本是下一阶段 |
| "数据过期了怎么办？" | 每个岗位保留核验日期与来源；正式提交前强制二次确认在招/薪资/批次；MVP 1.1 增加岗位状态复核机制 |

## 7. 结语

本项目最大的亮点是**把"不可解释的黑箱"拆成"硬门槛 → 证据匹配 → 人工确认"三层**，并诚实地标注了所有假设与边界。本次诊断与升级的目标，是让这套设计在讲师面前"看得见、说得清、验得证"：匹配分可拆解、AI 参与可展示、数据来源可核验。剩余的核心工作不在代码，而在证据——把 n=1 变成 n=6，把人工标注变成 AI+人工对照。
