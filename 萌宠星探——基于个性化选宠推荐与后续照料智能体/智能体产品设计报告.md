# 智能体产品设计报告

## 一、智能体产品概述

随着宠物经济的快速发展，越来越多人希望饲养宠物作为伴侣，但许多初次养宠者因缺乏经验，常因宠物与自身性格、生活方式不匹配而使自己不满意，宠物也得不到好的照顾，这样会增大饲养压力甚至导致弃养。因此，我们开发了基于AI 的宠物匹配助手-萌宠星探，通过分析用户的性格、偏好和诉求，科学推荐最适合的猫/狗品种，提升人宠契合度，提高人和宠物的幸福度，同时也减少因为盲目饲养带来的一些社会问题。

这个智能体可以通过用户提供特征与需求和宠物特征数据库对比，匹配合适的宠物；同时提供宠物品种的详细需求说明（如运动量、护理复杂度），帮助用户在饲养过程前和饲养中的理性决策；最后希望通过较好地匹配为用户提供选宠方案，提升主人与宠物的幸福感而降低弃养概率。

对于用户来说，避免“冲动养宠”，获得长期稳定的情感陪伴，提升幸福感；对于宠物来说，匹配更负责任的主人，减少被遗弃概率，改善动物福利；对于社会来说，可对接宠物店、领养机构，为用户提供更精准的选宠服务。

## 二、智能体产品市场定位

**目标用户群体：**

| 用户类型 | 特征 |
|---|---|
| 初次养宠人群 | 缺乏养宠经验，需要入门级建议 |
| 犹豫不决的潜在养宠者 | 需要根据性格、生活习惯、空间等匹配建议 |
| 父母为孩子选宠者 | 更关注性格温顺、安全、易养 |
| 老年人 | 希望宠物陪伴、互动低强度 |
| 忙碌的上班族 | 需求：省心好养、安静独立 |
| 有过养宠经验者 | 寻找更匹配的新宠种类 |

**竞品分析：**

| 产品/平台 | 核心功能 | 存在问题 |
|---|---|---|
| 百度搜索 / 小红书搜索 | 搜索宠物推荐内容、达人分享 | 信息杂乱、无结构化推荐、无法匹配个性 |
| 宠物App（如波奇网、狗民网） | 品种百科、论坛互动 | 不智能、推荐性弱、无问答互动 |

**本智能体产品差异化定位为：**

“人格匹配式宠物推荐助手+ 图文识别+ 智能问答”

**核心差异化：**

多轮对话匹配个性化推荐

→通过用户性格、作息、住房、爱好智能匹配宠物

图像识别+ 结构化信息整合

→上传图片识别宠物种类，结合性格图谱推荐同类

知识库+ 联网混合搜索能力

→精准、结构化回答，不靠模糊泛泛的模型生成

可嵌入任意平台（如小程序、客服系统）

→B 端灵活拓展，打通电商与线下领养渠道

对接用户画像与养宠偏好学习

→可进化为“养宠陪伴助手”，不仅推荐一次，更持续服务

**核心竞争力：**

| 能力模块 | 优势 |
|---|---|
| 智能推荐引擎 | 基于性格、空间、作息多维匹配 |
| AI图像识别 | 准确识别宠物种类，辅助推荐 |
| 多模态交互 | 支持文本 + 图片输入，提升用户体验 |
| 数据结构化 | 区别于内容平台，信息准确、聚合 |
| 本地知识库 + 联网融合 | 回答准确率与实用性并重 |
| 可定制化部署 | 满足企业个性化需求，提升商用能力 |

## 三、智能体产品需求分析

**需求收集方法：**

**1.访谈法**

访谈目标-了解用户在挑选宠物时的决策过程、痛点和没有解决的需求；探索用户对AI 助手辅助选宠的接受度和期望功能。

访谈对象-

有养宠计划的新手

现有宠物主（可能对现有宠物不太满意）

宠物行业人员（如兽医、宠物店主、救助站工作人员）

样本量：每类用户5 到8 人总计15 到20 人

**访谈问题大致示例：**

筛选问题

“您目前是否养宠物？如果养，是什么品种？养了多久？”“您最近是否有计划养新的宠物？如果有，在考虑哪些类型（猫/狗/其他）？”

核心问题

“您是如何决定养现在/计划中的宠物的？”（朋友推荐、网上搜索、宠物店建议等）

“在挑选宠物时，您最关注哪些因素？（如性格、体型、护理难度等）”“您是否遇到过因宠物与您的生活方式不合而困扰的情况？能否具体描述？

“现有的推荐方式（如百科、宠物店）有哪些让您不满意的地方？”“如果有一个工具能根据您的性格、住房条件等推荐适合的宠物，您希望它提供哪些信息？”

“假设您住在公寓且每天工作10 小时，您会担心养狗吗？最担心什么？”“在您的工作中，最常见的弃养原因是什么？”

**2.数据分析法**

访问宠物相关论坛、网站，收集、挖掘宠物论坛高频问题与关键词如：“哪种猫黏人”、“上班族”、“掉毛”、“预算”等。

**通过需求挖掘与洞察，提炼出了三类核心需求：**

-辅助决策类-用户需要得到客观工具代替主观猜测来降低试错成本；

-兼容性需求-宠物与喂养环境的适配性比外形更重要；

-长期喂养需求-用户缺乏对品种长期行为特征的认知。

| 需求级别 | 对应需求 | 优先级 | 产品解决方案 |
|---|---|---|---|
| 基本型需求 | 提供品种基础信息（体型、寿命、性格、价格、饲养基本情况等） | 高 | 知识库存储300+品种的标准化的分段内容与打标信息 |
| 期望型需求 | 个性化推荐（匹配性格/生活方式/预算等） | 高 | AI算法生成兼容性、匹配度评分，形成Top推荐 |
| 兴奋型需求 | 动态调整建议（如“您搬家后适合…”） | 中 | 用户数据记录，更新资料后重新匹配 |
|  | 上传图片智能识别宠物类型(如：朋友圈中别人发送不认识的宠物) | 中 | 智能体加入图片识别功能，并且提供相关宠物信息以及饲养匹配度建议 |
| 无差异需求 | 社交功能（如晒宠社区） | 低 | 暂不开发 |

核心需求与用户痛点

**核心需求：**

-解决信息不对称-用户不知道如何将自身条件（时间、空间、性格、预算）转化为宠物选择标准。

-降低决策风险-避免因冲动养宠导致弃养或长期痛苦。

**部分用户痛点：**

-新手养宠：怕选错宠物，后悔多年；

-宠物领养机构：退养率高，匹配没有依据；

-上班族：喜好狗但害怕没时间饲养。

**产品解决方式：**

-提供科学匹配建议和风险提示；

-提供匹配依据，宠物性格评分；

-推荐低运动的犬种。

## 四、智能体产品功能设计

本智能体产品是利用网络爬虫的数据，将其进行预处理（清洗、合并、分段等），形成知识库，再利用扣子平台上所支持的功能，搭建的一种结合了检索和生成两种能力的模型框架，主要通过首先检索相关文档或信息片段，然后使用这些信息来生成更准确、更有上下文关联的回答的RAG 垂类智能体，主要应用于帮助用户了解宠物的相关信息并根据用户需求与实际情况提出饲养建议。

**产品功能设计如下：**

**知识库部分：**

1. 数据收集

-定位目标网站：根据与部分养宠人士的交流以及网上查阅资料，选择所要爬取的目标网站。

-爬取数据：利用Python 爬取网站内容，主要宠物信息、文章、饲养法规等。

-数据预处理：将爬取的数据进行结构化处理，去除冗余信息，并将部分数据合并、整合，便于后续交给大模型进行分段处理。

2. 知识库构建

-文本数据训练：在扣子平台资源库中加入知识库，将数据预处理后的文本数据，进行投喂、训练，形成本地知识库资源。

**智能体部分：**

1. 感知与识别模块

-多模态输入：基于需求，用户更多是以文字为主以多轮对话形式与智能体进行问答，也有少部分需求，希望能上传图片，希望对图片进行识别，介绍其信息。

-意图识别：可通过配置关键词、模型识别方式，判断用户想法。2. 对话管理与状态维护

-关键参数提取：在问答过程中，智能体会记录对话中关键内容（喜欢动物种类、预赛、倾向性格）并存入数据库，埋点分析收集数据并且用户方便下次询问时，调用以往数据作为参考，回答更为精准、贴合用户实际需求。

-记忆管理：长期记忆功能，可通过变量和存储组件自行管理，在进行多轮询问时，能够将智能体注意力集中在用户特性上而去回答问题。3. 执行与工具调用

-使用到了图片识别插件，当用户上传图片时，进行图片识别，为猫狗宠物，会给予用户相关的信息以及饲养建议。

-在进行预调研时，了解到绝大部分用户饲养的宠物为猫猫与狗狗，所以网络爬虫部分也是以猫猫狗狗的相关数据进行爬取，但是考虑会有一部分需求不为这两种动物，比如乌龟、仓鼠等也都属于宠物范畴。这时会触发工作流，工作流中使用到了bing 搜索插件，在知识库无法回答问题时，进行联网搜索，保证对话的有效性。

-在用户谈及其他不涉及到宠物选择时，触发工作流，提示用户无法回答该类问题，请询问有关于宠物的问题，保证了该智能体的特性。4. 反馈结果与响应

-文本回复，支持Markdown 与变量混合输出。

-回答符合逻辑，言简意赅、通俗易懂，保持专业且确定的风格。

2. 工作流搭建

当用户想通过上传宠物图片来获取宠物信息时，或者用户问到非猫猫、狗狗如乌龟、仓鼠等不常见宠物时此工作流触发。

**工作流设计如下：**

![image](media/img_11.png)

工作流设计

**流程：**

①当用户询问到非猫猫狗狗的动物或者比较稀少未录入知识库的动物时，会调用bing 插件进行搜索返回给用户相关信息，保证智能体回答有效。

②当用户询问到非宠物相关的问题时，通过配置系统提示词，会友好地提示用户“不与宠物相关，请提问其他关于宠物的问题哦～”，并且引导用户询问相关宠物话题。

③用户有上传图片宠物（猫、狗），则通过大模型判断后，到知识库进行检索，返回该动物信息。

④用户有上传图片非宠物或者不是（猫、狗），知识库里无相关信息（因为上一级大模型设计可以返回具体的宠物名字，故知识库检索【最小匹配度】调得较高以过滤、返回相关知识库内容），则返回数据为空，最终提示用户“无法识别宠物，请上传清晰的宠物图片。”。

备注：当用户上传图片时，会先进行判断，判断有图片类型文件上传后，调用deepseek 大模型对图片内容进行解析，通过优化提示词，让大模型判断是否存

在宠物、判断其种类、判断其可能的品种，将相关信息精简、结构化后输入到下一级节点。

-意图识别率高，模型理解用户输入基本准确；

-流程闭环设计清晰，多数对话都有明确引导和结尾；

-调用逻辑清晰，API、知识库、插件等调用成功率高；

-上下文变量使用得当，能进行连续对话、状态记忆处理；

-对话交互自然，文字输出流畅，指令反馈及时。
